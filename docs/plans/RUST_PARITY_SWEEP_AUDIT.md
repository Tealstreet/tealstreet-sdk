## Prioritized actionable findings

1. **OKX inverse swaps: explicit #1302 exclusion, supported by TS today.**
   - PR: https://github.com/Tealstreet/tealstreet-sdk/pull/1302, final scope paragraph excludes inverse swaps and EEA X-Perps.
   - TS `packages/safe-cex/src/exchanges/okx/okx.exchange.ts:185` requests SWAP, `:189` accepts ctType linear OR inverse, `:372` derives inverse market base/quote/settle and `isInverse`, `:207` resolves underlying independently of SWAP suffix. Rust `sdk-rs/venues/okx/src/lib.rs:523` rejects every non-linear or non-USDT/USDC-settled contract, `:579` hardcodes isInverse=false.
   - Minimal safe implementation is more than removing the catalog filter: preserve contract-count order size/filled and native contract limits; convert order remaining/positions to TS display base units using inverse quote-value / current mark (not entry); inverse notional is native count * ctVal; preserve coin-denominated PnL semantics and convert account-risk USD totals with that currency's mark; currency balance map must identify base settlement. Current Rust `account.rs:892` multiplies native size by ctVal unconditionally and `:914` multiplies notional by mark, so both require the inverse branch. Preserve mark/index/funding subscriptions and exact symbols. Audit history fill/closed-position conversions as well. Add inverse fixture/native contracts/WASM copy coverage and an OKX+Binance replay set without increasing budget.

2. **OKX EEA X-Perps: explicit #1302 exclusion, supported by TS today.**
   - TS `packages/safe-cex/src/exchanges/okx/okxeu.exchange.ts:9` requests both SWAP and FUTURES, `:33` accepts only FUTURES `ruleType=xperp` with ctType linear/inverse. `okxeudemo.exchange.ts:7` inherits all of this. TS core `okx.exchange.ts:195` selects per-market instType; `:212` preserves compact dated X-Perp identity and `:222` pretty symbol.
   - Rust `lib.rs:421`/`:423` catalogs SWAP only, `:528` requires -SWAP, `:663` tickers SWAP; `wire.rs:25` Instrument lacks instType/ruleType/underlying fields. `account.rs:128`, `:140`, `:176`, `:179`, `:230` etc and `history.rs:443` all hardcode SWAP.
   - Minimal safe design: retain per-market instrument type, list SWAP+FUTURES only for EEA, filter FUTURES strictly xperp, merge those account snapshots and readiness as one scope without authoritative sibling wipes, route subscriptions/pending orders and symbol-scoped history/settings to that instrument type, preserve underlying-ID mark/index joins and dated IDs. Keyless public catalog versus signed account-instruments eligibility overlay must match TS. This is deterministic with documented fixtures; actual EEA eligibility needs live account keys, but that does not justify omitting production support.

3. **OKX definitive client-ID lookup: discovered supported capability gap (not explicitly stated in PR body).**
   - TS `okx.exchange.ts:126` overrides lookup: search store first; resolve known market; GET `/api/v5/trade/order?instId=<id>&clOrdId=<caller-id>`; map filled/canceled/mmp_canceled (`:81`); only native API code `51603` yields definitive=true; empty/malformed/no matching row is nondefinitive; other failures propagate. The method is read-only and does not mutate store.
   - Rust `sdk-rs/venues/okx/src/history.rs:323` rejects OrderByClientId. Wrapper `packages/safe-cex/src/exchanges/rust/rust.exchange.ts:239` routes native lookup ONLY for Hyperliquid and Paradex, so current OKX Rust loses the TS definitive behavior even if the native arm alone is added.
   - Minimal change: dedicated typed read/response arm using existing signed GET and existing order mapping, strict native symbol+client-ID validation, preserve native error code distinction, ensure no dirty store/WS/write action, route only OKX aliases through native SDK operation. Add open/partial/filled/canceled/mmp_canceled/missing/empty/wrong-ID/wrong-symbol/error/unknown-market/public-data tests. A found order must carry the caller ID/provenance and supported original native properties. Never convert HTTP/auth/parser failures to definitive absence.

4. **Binance USD-M / PM definitive lookup: roster crosscheck, supported by TS.**
   - Roster `docs/plans/RUST_REWRITE.md:307` says Binance USD-M/PM done. TS `packages/safe-cex/src/exchanges/binance/binance.exchange.ts:164` overrides lookup; Rust `sdk-rs/venues/binance/src/history.rs:167` explicitly rejects. 2. **Generic remote signing is unsupported by the Rust wrapper for TS venues that support it.** This is not explicitly a separate late venue PR limitation except Paradex (owned by other lane), but it is a shared source-level capability gap discovered while checking the disclosed single-signer limitation. Do not call this TS-unsupported or imply live credentials are technically required; protocol/host work is required. **Paradex remote signing is excluded by user and owned by the other lane.** If shared signing is added, coordinate scope so it does not modify that lane's Paradex contract.

3. **Binance/OKX definitive lookup forwarding looks absent in the common wrapper.** Outside late-PR ownership, but parent notified: wrapper constructor only forwards native client lookup for Hyperliquid/Paradex (`rust.exchange.ts:239–242`), while TS has real definitive overrides at `binance/binance.exchange.ts:164` and `okx/okx.exchange.ts:126`; inherited base lookup (`base.ts:893–903`) only sees open orders. Verify native implementations and expose them if this remains true. WOO/Orderly/KuCoin/ApeX do **not** have TS definitive overrides; their explicit native Query rejection is not a lost TS capability. Parent is auditing earlier PRs and Phemex separately.
