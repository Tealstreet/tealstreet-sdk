# MEXC futures negative joins

The shared production Session/Registry/probe/HPKE suite checks an independent
second valid pair and seven resident-preserving scenarios on mainnet. Both
COSIGNED and DELEGATED hosted testnet refuse before private I/O or attachment;
no sandbox is mapped. All traffic is loopback, not live venue certification.

The synthetic venue independently verifies singular API-key/time/signature
headers and hex HMAC of key + millisecond timestamp + actual query. It checks
native socket login too. Empty signing payloads can describe either WS login
or a private REST prerequisite, so replay targets query-bearing private reads;
those operation slots retain parameters and omit only time-window bounds. Full
old/new signing bytes must differ. Public discovery and tokenless heartbeat
cannot prove possession. Unknown requests and trading writes fail the fixture.

Refusals retain the loaded actor/provider, deterministic signature, owner,
fingerprint, holdings and original registrations. No production auth classifier,
readiness, origin, signing codec or shared refusal predicate changes.

The compiled unchecked-authentication checkpoint makes three verifier controls
and the real Session wrong-key assertion fail. Earlier compile/setup failures
are excluded from that sensitivity evidence. Wire verification fixes only this
family adapter. Run from `sdk-rs`:

```sh
cargo test --locked -j2 -p safe-cex-exchange-server --test negative_join_mexc -- --test-threads=1
```
