# Bitunix, Bitrue, Orderly, Phemex and Breakout Prop divergence audit

The frozen source/manifest parent is integration
`f853d56fd227c2106dba609141b1fdd44bcab125`. This audit branch starts directly
there, with no open feature ancestors. The earlier three-venue audit remains on
PR 7912; its reviewed head is cb3a126730b5622e9ae83c5e7f9d3bd761b07cce.

All 148 divergent rows in these five venue directories are frozen before
classification. Parse existing TOML rows, sort each venue by SHA256 of UTF-8
`divergence-audit:` + file.ts + `::` + symbol.ts, and retain every original note.
No substitution or status change enters this audit. This extends the earlier
ordering method to the user's entire named block: 147 notes contain CHOSEN,
while Phemex's reconciliation row is CORRECTED and is reported separately.

Across the entire block: **58 supported / 86 findings / 4 unresolved** out of
148 (39.2% / 58.1% / 2.7%). Restricting the denominator to the original
CHOSEN-containing notes gives **58/147 supported, 85/147 findings, 4/147
unresolved**. The additional CORRECTED-only Phemex row has an unpriced initial
queue/timer scheduling effect, separate from its declared error-return change.
Findings comprise **62 explanation gaps, 21 scheduling gaps and 3 behavior
differences**. All 86 findings are added as notes; statuses and targets remain
unchanged, with every historical annotation retained.

The three behavior findings are Bitunix iterations 9/19/44. Ordinary JSON stop
type text selects inherited members of a static source table; native own-only
lookup produces a different trigger value. They do not require inherited input
properties. An invalid OrderSide prototype probe and invalid Timeframe candidate
were excluded; valid enum/open-symbol witnesses support the distinct String
findings instead.

Breakout Prop's real eager wrappers, future-drop costs and staged mapper refusals
remain supported. Eight generic FORCED clauses gained actual source witnesses
for returned options, handler-key/callback lookup, login credentials/token,
placement instrument and configured request URL. Their existing causes were
corroborated rather than counted as new semantic defects. Breakout iteration 7,
toDxOrderType, remains unresolved: successful inputs/results are closed ASCII
enums, while its invalid-enum surrogate error probe lacks an admitted production
caller/consumer observation. Its exact original annotation is retained.

Orderly's exported base64url takes an unrestricted string argument; an executed
public call returns [D800,45,95]. The signing caller's narrower ASCII dependency
was not imposed as a new precondition on this exported function. Conversely,
ASCII regex classifiers, closed literal outputs and TextEncoder replacement
were not treated as retained-unit findings merely because their inputs can
contain a surrogate.

Phemex validateAccount and the Breakout timeout-to-validation chain were executed
through their actual public return boundaries. Their returned error fields
retain D800 before JSON output; these are public SDK data-return observations,
with no inferred UI consumer. Private helper-only diagnostic probes remain
subject to their unresolved caller/domain limits.

Source supplements record units, object identity, types, effects and errors
before serialization. Native counterparts for this block were inspected, not
newly executed. Phemex's nine-observation source supplement has two detected
in-memory source controls with restored passes. Bitunix's actual public Position
consumer supplement adds two detected source controls with restored passes. Detailed measured exits and
limitations are recorded in DIVERGENCE_BLOCK_GATE_EXITS.md.
