## Declared coverage shape

Each row runs **512 deterministic instances**, stopping at511:32 generations
by16 slots. Slots use12 exception/getter profiles;0..3 appear twice per generation.
They are not512 independent random draws. Generation varies input identity, text
length, numeric spelling, original amount and filled amount. Known sides alternate
BUY/SELL by generation; unknown/prototype side profiles remain unchanged. Both runtimes declare
the input recipe independently; Rust never decodes or re-encodes expected output
as its native input.

The side, length and numeric axes are correlated, not a full cross-product.
In particular, length65 is a BUY generation; length65 combined with SELL is
not exercised by this corpus and receives no discrimination claim.

The32 UTF-16 ID lengths include0,1,31/32/33,63/64/65/66,127/128/129,
255/256/257,511/512/513 and1023/1024/1025. Length65 reaches every row's native
path at192..207; the first mapper witness is192. This is a **text** boundary,
not array coverage. The sampled bodies produce fixed-size records or one-order
store calls; unbounded collections remain outside this experiment.

Numeric spellings cover signed zero, underflow, overflow, NaN/Infinity, parseFloat
prefixes, whitespace, integer precision boundaries, subnormal/minimum-normal and
maximum-finite values. Other retained profiles exercise symbol coercion failures,
inherited enum `constructor` keys, missing/empty token maps, getter errors,
repeated changing reads, matched-status casing, throwing store/emitter/logger
boundaries, and store mutation of the original mapped record before fill emission.
Native UTF-16, record fields, binary64 values, pointer identities, errors, state
and ordered access traces are observed directly. NaNs compare as a class;
payload/sign bits are not claimed. Independent native ID/amount/fill witnesses
precede their source value comparisons; aggregate native outcome totals are
checked after the corpus. No Rust output roundtrip is used.

Independent totals per row are384success/128failure,416/96 and480/32 respectively.
The update row stores480 records and observes96 fills; all rows include16 length65
input witnesses. These are constants from the recipe/protocol, not copied from
the returned corpus length or its outputs.
