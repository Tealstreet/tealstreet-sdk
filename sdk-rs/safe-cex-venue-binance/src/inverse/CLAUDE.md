# Binance inverse

Behavior follows [the maintained Binance sources](../../../../packages/safe-cex/src/exchanges/binance/CLAUDE.md),
specifically binanceinverse.api/types/exchange/ws-public/ws-private.ts.
This family module uses the canonical native Js graph and shared Scope, BaseExchange,
HTTP factory, Store and BaseWebSocket services. Imported Binance depth/dispatch
and signing algorithms retain their original owners.

Construction and REST belong to mod.rs/exchange.rs/api.rs; the socket bodies belong to
ws_public.rs/ws_private.rs. Both sockets receive Rt with the actual exchange as
this, and retain Weak<Shared> when capturing callbacks. The parent provides the
actual options, Store, xhr/publicXhr and REST lifecycle methods.

The shared constructor/runtime ABI is used by the actual native registry constructor. Registry
registration and parity claims follow the real installed bodies and binding
witnesses; the pending source census remains the implementation checklist.

The tables and strict wire records are generated by the existing Binance owner:
`node sdk-rs/safe-cex-venue-binance/scripts/types.mjs --inverse --generate`.
Default generation still covers the three original Binance variants unchanged.
The REST binding target uses actual terminal HTTP, shared signing/retry and Store;
it never supplies replacement venue methods. Its constructor control compiles the
preserved pre-port body and must fail before the restored six-case target passes.
`create_no_proxy` is the source public factory call at binanceinverse.api.ts:23;
existing venues retain their own factory call sites.
