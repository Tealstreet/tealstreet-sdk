# Binance inverse

Behavior follows [the maintained Binance sources](../../../../packages/safe-cex/src/exchanges/binance/CLAUDE.md),
specifically binanceinverse.api/types/exchange/ws-public/ws-private.ts.
This family module uses the canonical native Js graph and shared Scope, BaseExchange,
HTTP factory, Store and BaseWebSocket services. Imported Binance depth/dispatch
and signing algorithms retain their original owners.

Construction and REST belong to mod.rs/exchange.rs/api.rs; the socket bodies belong to
ws_public.rs/ws_private.rs. Both sockets receive Rt with the actual exchange as
this, and retain Weak<Shared> when capturing callbacks. The parent provides the
actual options, Store, xhr/publicXhr and REST lifecycle methods.

The shared constructor/runtime ABI is used by the actual native registry constructor. Registry
registration and parity claims follow the real installed bodies and binding
witnesses. The source census maps the API, class, socket and generated type
bodies; representation choices stay explicit in those rows. Measured binding
and compiling controls are recorded in [PORT_REVIEW.md](PORT_REVIEW.md).

The tables and strict wire records are generated by the existing Binance owner:
`node sdk-rs/safe-cex-venue-binance/scripts/types.mjs --inverse --generate`.
Default generation still covers the three original Binance variants unchanged.
The REST binding target uses actual terminal HTTP, shared signing/retry and Store;
it never supplies replacement venue methods. Its constructor control compiles the
preserved pre-port body and must fail before the restored binding target passes.
`create_no_proxy` is the source public factory call at binanceinverse.api.ts:23;
existing venues retain their own factory call sites.


The non-socket accepted-owner review is scoped to the seventeen compiler-discovered
owners in `scripts/inverse-accepted-owner-list.json`. Run
`node safe-cex-venue-binance/scripts/inverse-accepted-contracts.mjs` from `sdk-rs`.
It uses the maintained rustdoc inventory and native production probe generator;
raw helper arguments and the exchange entrypoints require executed observations,
not classification-only or blanket typed-input receipts. Generated records retain
their object front gates, every field's native bits/presence, and the public Vec
alias's member admission. The class witnesses use the existing primitive REST
runtime with actual constructor, Store, signing, promises and callback bridge.

`python3 safe-cex-venue-binance/scripts/inverse-accepted-controls.py`, also from
`sdk-rs`, compiles isolated helper, record-front-gate and generic invoke/listen
faults. Each must fail its named native observation, then exact source restoration
must pass all seventeen owners. It never counts a compiler error as a runtime
failure. This finite native/default corpus complements the actual-source REST,
order and socket suites; it does not claim the full feature matrix or replace
the separate socket-helper accepted-owner cohort.
