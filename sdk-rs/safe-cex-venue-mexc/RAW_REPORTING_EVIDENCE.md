The raw-reporting FINDING is a **behavior defect**, not a rationale gap or an established measurement failure. Source passes `response.data.message || err.message` to the actual reporter. Premature native stringification changes `7` to a prefixed string report, loses an object's numeric `message`, and turns a failed coercion into a reported string followed by Store fallback. Validation separately omits `response.data.message`/`msg` precedence. Earlier position tests did not measure these inputs.

This implementation retains the selected JSON value, invokes source-order fallible coercion only in the reporter's String site, and preserves raw worker and main-thread report values. The shared runtime gains a required raw-value reporting hook; all eighty pre-existing in-tree implementations are test doubles and explicitly reject an unexpected raw report. The new MEXC runtime witness implements and inspects that hook. Embedders must implement the added capability; there is no stringifying default.

Retained JSON and metadata boundary choices use [the canonical declaration](../parity/MANIFEST-SPEC.md#owned-snapshot-vs-live-alias). The actual Source formatter owns undefined `config`, `baseURL`, and `timeout` slots in the witnessed cases; native report JSON omits them. Source receives the raw console argument while the existing native console capability receives text; retaining that logging interface avoids a second object-valued console protocol. Structured report/event values use the new raw path. Borrowed futures still defer GET until polling and lose unpolled work; keeping the common caller-owned future API avoids an implicit venue executor. These costs are separate from the repaired reporting defects and use [the taxonomy](../parity/MANIFEST-SPEC.md#divergence-taxonomy).
